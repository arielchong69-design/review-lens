# 复盘镜 · 投资决策复盘与学习

投资者复盘时通常只记得盈亏。复盘镜把**交易记录、当时理由、市场数据和事件**对齐到同一条时间线上，在每个决策点画一条**信息截止线**，把“当时能知道的”和“事后才知道的”分开，再用规则和 AI 做结构化复盘，最后把结论沉淀成**下一次决策前自动检查的清单**。

- 在线地址：https://review-lens-24x.pages.dev
- 演示视频：`<可选>`

---

## 1. 目标用户与要解决的问题

**目标用户**：有一定交易频率的个人投资者，会记录或愿意补记交易理由，希望提升自己的决策质量，而不只是看收益曲线。

**核心问题**

| 用户的现状 | 后果 | 复盘镜的做法 |
|---|---|---|
| 只记得盈亏，想不起当时的依据 | 复盘变成“赚了就是对、亏了就是错” | 交易记录强制区分**理由 / 关键假设 / 退出计划**，并和当时的行情、事件放在同一条时间线 |
| 复盘时用到了当时不可能知道的信息 | 后见之明，学到错误的经验 | 每个决策点划**信息截止线**；AI 分两步，第一步**拿不到**任何事后数据 |
| 结论停留在“下次注意” | 不能复用 | 经验沉淀为清单，带**可自动检查的触发条件**，下次决策前逐条对照 |

## 2. 核心链路

```
导入交易(CSV/表单/示例) ──► 取数（扶摇：前复权+不复权日K、沪深300、可选的行业/概念比较指数、日期范围异动解读）
        │                         │ 失败 → 离线快照 → 仍失败则标记缺失，不生成相关结论
        ▼                         ▼
   交易校验 ───────────► 时间线对齐（对齐交易日、核对成交价、事件按“首次可见时间”分段）
                                  │
                ┌─────────────────┼──────────────────┐
                ▼                 ▼                  ▼
          事前可知证据        当日（部分可知）      事后证据
          (T-1 收盘及以前)     (T 日走势)          (T+5/20/60、持有期、卖出后)
                │                                    │
                ▼                                    ▼
      AI 第 1 步：只看事前 ──► AI 第 2 步：看全部，检验假设、归因、提炼经验
                │                                    │
                └──────► 输出校验（引用存在性 / 后见之明 / 数字溯源 / 合规）◄─┘
                                  │  AI 不可用 → 规则引擎生成同结构复盘（明确标注）
                                  ▼
          复盘报告：事实 / 规则推断 / AI 推断 / 不确定 分开标注，每条可点开看来源
                                  ▼
          经验清单（去重计数）──► 决策前检查：用最新行情逐条判断是否触发
```

## 3. 关键设计

### 3.1 区分事前可知与事后信息（防后见之明）

- **价格类**：事前指标只用交易日 **T-1 收盘及以前**的K线（T 日收盘在决策时还没发生）；T 日走势单列为“当日（部分可知）”。有自动化测试验证：把 T 日之后的行情乘以 3，事前证据完全不变。
- **事件类**：用异动解读的 `first_publish_time`（信息首次可见时间）而不是发生时间。交易填了时间（如 10:15）就精确比较；没填时间的同日事件标为“时序不确定”，不强行归类。
- **AI 结构隔离**：第 1 步提示词里只放 `ex_ante / same_day` 证据（有测试断言提示词中不含任何事后证据 ID）；第 2 步才给全部证据，并要求“事后证据只能检验假设，不能用来指责当时应该知道”。
- **输出兜底**：第 1 步结果里若引用了事后证据或出现“后来、最终、结果证明”等措辞，该条直接移除并在“AI 输出校验”里展示。

### 3.2 结构化复盘：事实、归因、偏差、不确定性

| 类别 | 由谁生成 | 怎么保证可信 |
|---|---|---|
| 事实（数字） | 确定性代码 | 每个数字是一条证据，带接口、request_id、时点、单位、计算口径 |
| 行为偏差 | 规则引擎（7 条） | 规则与阈值公开展示；样本不足时显示“数据不足”而不是“未触发” |
| 过程 × 结果 | 规则打分 | 过程分 5 项（理由、假设、退出计划、是否守计划、追涨时是否考虑风险）× 超额收益，区分“运气好”和“方法对”；违背自己写下的计划一票否决 |
| 假设检验、归因 | AI | 必须引用证据 ID；无引用的“事实”降级为推断，无引用的归因置信度降为“低” |
| 不确定因素 | AI / 规则 | 单列展示 |

规则偏差：追涨买入、缺少退出计划、理由缺失、情绪化卖出、止损未执行、持有周期偏离计划、处置效应（组合层面）。

### 3.2.1 证据相关性校验（确定性，不增加 AI 调用）

每条核心结论（理由评估、风险信号、假设检验、归因）的最终标签由校验器决定：**结构化校验通过 / 证据有限 / 无法判断**。AI 自评只能降级，不能升级。

| 环节 | 做法 |
|---|---|
| 证据类型与时序 | 每条证据按 ID 结构确定类型（走势、波动、位置、量能、基准、成交、结果、持有、事件、**用户当时记录**、**规则检查结果**）和时序（决策前已知、决策时点已知、当日部分可知、同日时序不确定、决策后产生） |
| 主题对照表 | AI 为每条结论选一个主题（固定枚举），主题决定可引用的证据类型和必需的证据类型；类型不匹配的引用被移除，然后**重新评估**结论 |
| 结构化断言 | “退出计划是否填写”“某规则是否触发”这类结论附带断言，直接对照交易记录与规则结果核对，与主题无关；与记录矛盾的结论隐藏 |
| 数值锚定 | 数值类结论必须写出所引用证据中的数值，用于发现“主题标错但引用了同类型证据”的情况；被移除的主题外证据若数值仍出现在结论中，说明结论有部分内容没通过主题校验，不能整体通过 |
| 时序 | 事前结论引用决策后证据 → 整条移除；“当日部分可知”“同日时序不确定”的证据不能单独支撑事前结论；判定假设“成立/不成立”必须有决策后证据；规则结果继承其所依据数据的时序 |
| 数据覆盖 | 证据库不含财务、经营、行业或板块数据，这类假设一律“无法判断”，行业归因最高“证据有限” |
| 失去支撑 | 降级为推断并在正文前加“（证据有限）”；原本声称有证据、引用全部失效且数字无法溯源的结论直接隐藏 |

“结构化校验通过”只表示：证据存在、时序适用、类型与主题匹配、数值可溯源（或结构化断言与记录一致）。**不代表语义或因果关系已被验证**，页面上会同时显示这句说明。

### 3.3 沉淀为可复用的学习

- 复盘里触发的偏差和 AI 提炼的经验，可一键加入**经验清单**；相同条目合并并累计“出现在几笔交易里”。
- 规则类条目自带**可自动检查的条件**（例如“近 20 日涨幅 ≥ 15%”“计划里没有止损”）。
- **决策前检查**：输入代码、理由和退出计划，用最新行情按复盘时**同一口径**计算指标，逐条显示“需要注意 / 已满足 / 请自己对照 / 无法自动判断”，并给出“你过去在相同信号下的历史表现”（明确标注为历史统计、不代表未来）。
- 可以把这次决策直接记入交易记录，成交后补价格，形成闭环。

### 3.4 数据缺失、冲突、过期、失败时不静默

| 情况 | 处理 |
|---|---|
| 实时接口失败 | 超时、网络错误、上游不可用或限流时先自动重试 1 次；仍失败则退回离线快照，界面和证据上标注“离线快照”及快照时间 |
| 快照也没有 | 标记缺失；依赖它的结论不生成（例如基准缺失 → 超额收益显示“—”并说明原因） |
| 成交价超出当日最高/最低价 | 标为数据冲突，相关结论置信度降低 |
| 交易日期是非交易日 | 对齐到下一个交易日并提示核对 |
| 未填成交价 | 用当日不复权收盘价代替，标为“假设” |
| 事件接口返回空 | 按接口文档提示“空列表也可能是服务降级，不代表没有事件” |
| 事后窗口未走完 | 显示“—”并写明行情截止日 |
| 卖出数量超过记录持仓 | 超出部分不计入盈亏并提示 |
| AI 超时 / 非 JSON / 未配置 | 切换到规则引擎生成同结构复盘，标题处写明原因 |

“数据状态”页列出本次每一次调用的状态、request_id、获取时间、条数、最新日期和耗时；还提供**故障演练**开关（模拟 K 线、事件、基准、比较指数、快照、AI 失败），用来验证以上降级逻辑。

### 3.5 第二比较基准：行业指数与概念指数分开

沪深 300 回答“跑赢大盘了吗”，但答不了“是个股的问题还是整个行业都在跌”。因此每笔交易可选填一个**同花顺行业或概念指数代码**（`.TI`，如白酒 881273.TI），作为沪深 300 之外的第二比较基准。沪深 300 仍是主基准，第二基准只是补充维度，获取失败不影响主链路。

**基准如何选、如何核实**

1. **由用户填写，系统不猜**。没有用“名称相似”或“AI 判断”去自动匹配行业，避免把概念指数错当成所属行业。
2. **核实名称与类型**：用扶摇 `ths-index-list?tag=industry` 和 `tag=cn_concept` 两份目录查到该代码，页面显示**实际名称**和类型（行业指数 / 概念指数）。两份目录都查不到 → 不使用该基准并说明原因；目录接口失败 → 类型显示“类型未核实”。
3. **核实关系**：用 `ths-stock-list` 查该指数**当前成分股**，判断标的是否在其中，得到三种角色：

| 情况 | 页面上的叫法 | 能否称为“所属行业” |
|---|---|---|
| 行业指数，且标的是当前成分股 | 所属行业指数（按当前成分判断） | 可以 |
| 概念指数，且标的是当前成分股 | 相关概念指数（该股为当前成分股） | 不可以 |
| 标的不在成分中，或成分无法获取 | 用户指定的比较基准 | 不可以 |

**加了行业基准，结论不会因此变“更充分”**

- 相对行业/概念指数的收益只说明**表现差异**，不说明原因。每条相关证据的计算口径里都写了这一点。
- 归因“行业或主题”最高只能是“证据有限”；角色为“用户指定的比较基准”时，用它检验假设也最高“证据有限”。
- 校验器检查措辞：除“行业指数 + 当前成分股”外，结论里出现“所属行业”会被降为“证据有限”并说明原因。
- 事前/事后隔离不变：事前只用比较指数 T-1 及以前的 20 日涨跌幅，交易后的比较指数收益和相对收益都是事后证据。

**已知限制**

- **历史成分无法核实**：扶摇只提供当前成分股。交易发生时该股是否已属于这个指数，系统无法确认，页面每次都会写明。
- **指数可能比交易更晚才有行情**：例如 AI应用（886108.TI）行情从 2026-01-13 开始，晚于示例中 2026-01-12 的同花顺买入。这种情况会提示“决策时该指数尚无数据（可能尚未发布）”，该笔不计算相对比较指数的收益，“行业或板块”类假设标为“无法判断”，沪深 300 比较不受影响。
- 扶摇文档里的示例代码与目录实际名称不一致（如文档示例 886042.TI 在目录中是“存储芯片”），所以示例交易里的代码都在目录与成分股里逐一核实过（2026-10-25）。

### 3.6 合规边界

- 不预测涨跌、不给买卖或仓位建议、不承诺收益。AI 提示词中写明，输出端再用规则过滤（直接买卖建议、目标价、确定性预测、涨跌预测、收益承诺五类），命中整句替换并记录。
- 经验只允许是“决策过程”层面的规则；被过滤的经验不会进入清单。
- 示例数据为构造的匿名交易；API Key 只存在服务端环境变量，前端和仓库中都没有。

## 4. AI 的角色

| 环节 | AI 做什么 | 不让 AI 做什么 |
|---|---|---|
| 事前评估 | 判断理由与当时证据是否一致；把理由拆成可检验的假设；指出当时可见的风险 | 看到任何事后数据 |
| 事后检验 | 逐条检验假设（成立 / 不成立 / 无法判断）；按 6 类因素归因并给置信度 | 自行计算新数字；给买卖建议 |
| 经验提炼 | 把教训写成下次可执行的过程规则 | 写“下次买某只股票” |

所有指标计算、时间线对齐、偏差判定都由确定性代码完成，AI 只负责语义理解和归纳。模型：DeepSeek `deepseek-chat`（JSON 输出模式，temperature 0.2）。

## 5. 数据来源

| 数据 | 接口 | 用途 |
|---|---|---|
| A 股日 K（前复权） | `GET /api/a-share/prices/historical?adjust=forward` | 收益、波动率、高点距离、量比（避免分红送转造成跳空） |
| A 股日 K（不复权） | 同上 `adjust=none` | 核对成交价是否在当日价格区间；补全缺失成交价 |
| 指数日 K | `GET /api/a-share-index/prices/historical`（000300.SH） | 基准与超额收益 |
| 日期范围异动解读 | `GET /api/news/anomaly/analysis`（单次 ≤365 天，自动分段） | 事件时间线，按 `first_publish_time` 判断事前/事后 |
| 同花顺指数目录 | `GET /api/a-share-index/catalog/ths-index-list?tag=industry` / `tag=cn_concept` | 核实比较指数的名称与类型（行业 / 概念） |
| 指数成分股 | `GET /api/a-share-index/constituents/ths-stock-list` | 判断标的是否为该指数**当前**成分股 |
| 标的检索 | `GET /api/meta/tickers/search` | 决策前检查时用名称找代码 |

统计口径：收益为收盘到收盘；成交价相关收益 = 前复权收益 × (当日不复权收盘 / 成交价)；年化波动率 = 20 日日收益标准差 × √244；超额 = 个股收益 − 沪深 300 同期收益；相对比较指数 = 个股收益 − 比较指数同期收益（同一对齐日期）；时区 Asia/Shanghai；金额单位元，不含交易费用。

```bash

cp .dev.vars.example .dev.vars    # 填入 Key
```

## 7. 已知边界与未做事项

**已知边界**
- 事件只用了扶摇“日期范围异动解读”，没有接公告全文和新闻；事件时间单位文档注明“待核实”，代码按数量级推断并在证据中标注推断方式。
- 交易日历接口只覆盖近一年，因此以 K 线日期作为交易日判断依据。
- 指数 K 线只支持近 5 年，更早的交易无法计算超额收益（会明确提示）。
- 收益不含手续费和税；FIFO 配对；不支持融资融券、港股、基金。
- 规则阈值（如追涨 = 买前 20 日涨幅 ≥15% / 贴近 60 日高点且放量 / 买入当日涨幅 ≥7%）是经验值，未经大样本校准；样本少时处置效应等结论不稳定（界面已提示）。
- 证据相关性校验是“类别 + 数值 + 结构化字段”层面的确定性检查，不是语义蕴含或因果验证。以下情况仍可能通过：主题与数值都对，但推理方向或因果解释错误（例如“距高点 -16.84%，支持‘未回本’的说法”）；结构化断言只证明了“理由已填写”，结论对理由的解读并未被验证（页面会注明“其余解读未经验证”）；事件类证据只核对类型与时序，不核对事件内容是否真的支持结论。
- 清单和复盘结果保存在浏览器本地，换设备不同步。

**未做事项**
- **未接入 iFinD MCP**。评估过它的市场宽度、资金流、宏观、政策新闻等数据，这一版没有接，原因：
  - 自然语言查询的返回结构和口径不固定，难以做成可复现、可溯源的证据；
  - 新闻、公告的发布时间与可见时间不一定能确定，宏观数据还有发布滞后和修订问题，容易把事后数据当成事前证据；
  - MCP 是会话式协议、独立端口，还有配额和并发限制，放进 Pages Functions 会增加新的失败点；
  - 账号对各类数据的权限没有逐项确认，不能按文档默认都能用；
  - 对复盘最直接有用的“行业/主题相对表现”维度用扶摇已有接口就能做（见 3.5），所以先做这一项。
- 没有账户体系与券商交割单自动导入（目前用 CSV 模板）。
- 没有对 AI 归因做系统化的人工评测集，目前只有规则校验和人工抽查。
- 没有做风格基准（大小盘、价值/成长），比较指数也不会自动推荐，需要用户自己填写代码。
